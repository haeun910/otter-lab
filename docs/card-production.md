# 승인한 카드뉴스 제작 규칙

2026-10-07에 확인한 **설명글 + 도식 + 쉬운 용어 한 줄** 구성을 기본으로 사용합니다. `config/card-production.json`이 공통 설정과 이미지 프롬프트의 기준입니다.

## 내용과 디자인

- 한 편에 주제 하나. 뉴스 확인 → 주제 확정 → 원문 조사·분석 → 구성안 확정 → 문구 작성·내용 검수 → 이미지 생성 → 직접 확인·저장 순서입니다.
- 기본 7장: 표지 1 + 설명 5 + 정리 1. 원문에 없는 비교·한계·수치로 장수를 채우지 않습니다.
- 일반인과 직장인이 이해하는 신문식 설명을 우선하고, 개발자에게도 도움이 되는 작동 원리와 이용 조건을 쉽게 풉니다. 개인적 조언·감상·전망을 끼워 넣지 않습니다.
- 설명 본문은 2~4문장, 100~220자 안팎(90~260자 허용). 흐름·비교·체크리스트 도식은 2~4개 짧은 항목, 용어 풀이는 한 문장입니다. 제목만 바꾼 반복이나 줄글만 가득한 장은 피합니다.
- 마지막 정리에도 요약 설명글을 두고, 세 가지 핵심을 체크리스트 도식으로 표시합니다.
- 정사각형. 따뜻한 아이보리 종이, 진한 숲 초록 제목, 대비가 높은 밝은 정보 패널과 가장자리 숲속 연구소 일러스트. 세이지·코랄·머스터드 포인트를 사용합니다.
- 첫 페이지는 메모하는 메인 수달로 고정합니다. 설명 장의 수달과 배경은 정보 영역을 침범하지 않도록 작게 배치합니다. 역할별 10종 설정은 유지됩니다.
- 하단에는 두 자리 페이지 번호 · 발바닥 · `@otterlab.ai`만 표시합니다. 출처·면책 문구는 카드 이미지에 추가하지 않습니다.
- 캡션은 친근한 요약, `다음 소식에서도 만나요. 🦦`, `원문을 보고 싶다면? 👇` 아래 실제 원문 출처. 해시태그는 주제·독자에 맞게 정확히 5개입니다.

승인한 원본 표지와 설명 장을 `public/card-style/approved-cover.png`, `approved-explainer.png`에 보관합니다. 이미지 요청마다 이 두 파일을 실제 레퍼런스로 전달하며, 해당 기사의 문구는 재사용하지 않습니다.

## 코드와 프롬프트

| 위치 | 역할 |
| --- | --- |
| `config/card-production.json` | 기본 모드·레이아웃·분량·레퍼런스·모델 설정·디자인 프롬프트 |
| `src/lab/gen/prompt.ts` | 원문 근거로 본문·diagram·glossary·캡션을 쓰는 공통 규칙 |
| `src/lab/gen/quality.ts` | 설명 부족·반복·본문과 도식의 근거·용어 정확성 검수, 지적된 장만 보완 |
| `src/lab/gen/production.ts` | 카드별 이미지 프롬프트, 도식·용어 구성 검증, 변경 감지 |
| `app/api/card-image/route.ts` | 주인 인증을 거쳐 한 장씩 전체 이미지 생성 |
| `src/lab/gen/imageServer.ts` | 레퍼런스를 넣은 OpenAI Images API 요청과 정사각형 PNG 검증 |
| `src/lab/render/generatedCards.ts` | 완성한 장 보관·재시도·수정한 장 감지·원본 내보내기 |

소장실의 **카드뉴스 기본 제작 방식**에서 이미지 디자이너의 추가 프롬프트를 수정하거나 승인한 제작 규칙으로 복원할 수 있습니다. 설정은 기존 브랜드 데이터와 함께 로컬 및 Supabase에 저장됩니다. 직원 명부의 문구 작성 지시문도 그대로 사용할 수 있으며, 공통 편집 규칙이 우선합니다. 기존 저장 설정에 새 항목이 없으면 승인한 제작 방식이 적용됩니다. 기존 초안 문구는 자동으로 덮어쓰지 않습니다.

## 연결과 사용

배포 서버에 `OPENAI_API_KEY`를 등록합니다. 기본 모델은 `gpt-image-1`, 품질은 `high`, API 요청 크기는 `1024x1024`입니다. `OPENAI_IMAGE_MODEL`과 `OPENAI_IMAGE_QUALITY`로 서버 설정을 조정할 수 있습니다. 모델 이용 권한이나 조직 인증이 필요하면 API의 403 응답에 따라 확인합니다. 키에는 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다. 키가 없으면 연결 필요 상태를 표시하며, 배경에 글자를 얹는 결과로 대체하지 않습니다.

문구와 구성안을 확인한 뒤 인쇄기에서 **필요한 카드 이미지 생성**을 누릅니다. 생성에는 API 요금이 발생합니다. 한 장씩 생성·저장하고 실패하면 그 지점에서 멈춥니다. 다시 누르면 유효한 완성본은 건너뜁니다. **N장 다시 생성**은 그 한 장만 새로 생성하는 명시적 작업입니다. 저장·미리보기는 이미지 API를 호출하지 않습니다.

원본 PNG는 브라우저의 IndexedDB에 저장하고, 이미지 ID·분량·변경 정보만 초안에 기록합니다. 큰 이미지 데이터를 localStorage나 Supabase JSON에 넣지 않습니다. **원본은 만든 브라우저에 보관되므로 다른 기기나 브라우저 데이터 삭제 후에는 원본을 다시 가져오거나 생성해야 합니다.** 게시물 원본은 PNG로 내려받아 보관하세요. JSON 백업에는 이미지 파일이 포함되지 않습니다.

본문·도식·용어·역할·페이지 번호·전체 장수·디자인 프롬프트가 바뀌면 이전 이미지는 저장할 수 없고 수정한 장을 다시 생성해야 합니다. 캡션만 바꾸면 이미지 재생성이 필요 없습니다. PNG는 생성된 원본 그대로 내보냅니다. 승인 예시 파일은 1254×1254이며, 앱 API의 새 생성 요청은 1024×1024입니다. 정사각형 여부와 파일 형식을 확인하지만 한국어 오탈자·정보 배치의 최종 확인은 게시 전에 사람이 진행합니다.

연결 검증은 `npm test`, `npm run typecheck`, `npm run build`, `npm run preview:build`로 수행합니다. 이미지 제공업체 테스트는 실제 레퍼런스 파일과 모의 응답을 사용하며 유료 외부 호출을 하지 않습니다. 실제 API 키가 등록된 배포에서는 한 장을 생성해 한글·레이아웃·연결 상태를 확인한 후 7장을 진행합니다.
